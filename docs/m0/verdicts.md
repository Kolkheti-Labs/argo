# M0 spike verdicts

Each verdict quotes the `VERDICT` line printed by `spikes/run.sh S-X` on the
clean host, the commit it ran at, and the design consequence.

| Spike | Verdict | Run | Consequence for M1–M3 |
| --- | --- | --- | --- |
| S-A chained-call atomicity + re-entry | **GO** | hetzner2 2026-09-02, `cargo test -p spike_integration_tests`, 7/7 | Settlement as state-write + chained token legs is safe: a failing last leg reverted the state write and the token transfer (`ProgramExecutionFailed("Guest panicked: Internal asked to fail")`, all balances unchanged). Self re-entry works and a top-level call into the internal entrypoint is rejected, so `repay_flash` can be an internal self-call gated on `caller_program_id`. 10 chained executions accepted, 11 rejected (`MaxChainedCallsDepthExceeded`): flash loans and liquidation chains must budget ≤10 legs. |
| S-B custody rule | **GO** (builtin token) | same run | Vault = token-owned PDA claimed via chained `InitializeAccount` under Argo's seed; anyone credits it, only Argo debits it by seed. Wrong seed → `InvalidAccountAuthorization`; user-signed debit → `Sender authorization is missing`; credit before claim → `ClaimedUnauthorizedAccount`, so `create_market` claims both vaults first. Testnet registers the builtin `token` (no authorities) and no `clock`/`ata`/`vault`: M1 targets the builtin behind a `token_core` adapter; accrual clock source is an M1 decision. |
| S-C event surface | **NO-GO** (as expected) | hetzner2 2026-09-02, `spikes/S-C/run.sh` | v0.2.4 `ProgramOutput` and `Block` have no event field (source) and the RPC payloads for an executed tx carry none (`evidence/localnet/S-C-*.json`). Reference liquidator/monitor observe by PDA polling: 8.8 ms per `getAccount` on localhost, so a 200-market/1000-position sweep is ~10 s naive, far less with the block-tail follower design in S-C.md. Events landed on LEZ `dev` after v0.2.4 (PR 705/707, indexer `getEvents`); the observation layer sits behind a trait so M4 swaps to events when a tag ships them. |
| S-D compute budget | **GO** | hetzner2 2026-09-02, `spikes/S-D/run.sh` | Per-execution cycles: Argo supply-shaped leg 239k, builtin token Transfer 131k, Argo leg emitting two chained calls 271k, self-call leg 74k; a liquidate-shaped chain (Argo + 2 token legs + internal) totals 607k, 1.9% of the 32M per-leg budget and safe under a future tx-wide budget. Heavy arithmetic costs ~5.3k cycles per mul_div-dense iteration (bitwise 256/128 division), so M1 uses a cheaper widening divide. **Account size dominates**: a 1 KB state account costs 544k cycles, 10 KB 4.8M, 50 KB 23.7M (74% of budget). Every Argo account stays under 1 KB; `Config`'s enabled sets are fixed-size. |
| S-E fee within deshield | **GO with a design change** (fee half N/A) | hetzner2 2026-09-02, `spikes/S-E/run.sh`, wallet v0.2.4 vs local sequencer | v0.2.4 has no transaction fees, so "fund the fee inside the deshield" is vacuous today. The live rule: a deshield into a never-initialised public account is rejected by the privacy circuit (`Cannot claim unauthorized account`, E0b), so the SDK first initialises the ephemeral account with its own key (E0, public tx, owner becomes `authenticated_transfer`), then deshield (E1: A=300) → public op signed by A (E2: A→B) → reshield to a fresh private note (E3: A=0, P2=200). One extra public tx per private interaction, visible on-chain as A's init. Linkability check (E4) needs a block decoder (ids are not base58 in raw blocks); the wallet's tx dumps show A co-appearing only with B and Argo-side accounts. Re-test when fees land (PR 801). |
